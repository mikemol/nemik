# nemik

*Standards-first project management over federated agent workstreams: what it guarantees, where its architecture is (and is not) modular, and the standards it is derived from -- every sentence below is the projection of a claim a check verified.*

## What nemik Guarantees

Every workstream's queue has exactly one reader in this codebase — adapter.py's queue_graph() is the only function that calls mtools' store.load(), so a schema change in the state file's shape is mtools' problem to absorb once, not a second parser's problem to notice [@single-writer-boundary]. Nemik-check's exit code means exactly one thing — 1 if and only if some workstream's queue produced an sh:Violation, 0 otherwise — which is what luthen's own witness (W81) parses, so the exit code is a contract other repos' automation already depends on, not an implementation detail free to drift [@exit-code-is-the-verdict]. Every run of nemik-check first prints grep-stable provenance — one line per fact, prefixed literally `provenance: nemik` and `provenance: queue <repo>`, naming nemik's own commit and each queue's committed/uncommitted/untracked state — so a verdict can be traced back to the source it was computed from [@provenance-lines-are-stable]. An unclaimed cross-repo block prints the literal token UNCLAIMED, and that token is read by other repos' own tick loops (paths-forward-loop skill §4.2) as their signal to mint a claiming waypoint — so nemik-inbound's output format is itself part of the fleet's coordination protocol, not just a human-readable report [@unclaimed-is-a-literal]. A waypoint symbol matching anything other than W followed by digits is flagged by SHACL as nonconforming, which is how nemik enforces mtools' own invariant that a symbol is an identity, never a position, and never reused [@symbol-pattern-is-enforced]. Nemik's own build fetches nothing from the network — the mikemol-pathsforward dependency it writes the queue through resolves to a wheel vendored in this repo at a pinned commit, not a git URL resolved at build time (nemik:W6, H1) [@hermetic-vendoring]. A cross-repo reference is always the two-part form <repo>:W<n>, and adapter.py resolves both that form and a bare local W<n> to the same kind of IRI, so a citation reads identically whether it names this workstream or another one [@cross-repo-citation-form].

## Standards It Is Derived From

Every waypoint's status is asserted through the OSLC Change Management oslc_cm:state property, with nemik's own four-valued vocabulary (Ready, Working, Blocked, Done) as its range — OSLC CM supplies the property, not the values, since mtools' status strings have no standard state URIs of their own to map onto [@oslc-cm-state-vocabulary]. Every parsed ledger line becomes a W3C PROV Activity — carrying prov:startedAtTime and, when the line names a symbol, prov:used pointing at the waypoint it acted on — so interrupt effort and forecast effort land on the same graph the enables/blockedOn edges already join, queryable by the one vocabulary rather than a bespoke one [@prov-activity-shape]. Nemik-metrics emits the Prometheus text exposition format exactly — brace-delimited, comma-separated, double-quoted label values — so vmagent's importer (or any other Prometheus-compatible scraper) reads it with no translation layer [@prometheus-label-format]. SHACL is the one conformance language nemik enforces the fleet's queues against — pyshacl is imported nowhere but check.py, so there is exactly one place a shape can be added, relaxed, or read, not several independently-drifting validators [@shacl-is-the-one-validator].

## Modularity: What Is, and Is Not, Isolated

Adapter.py imports no other nemik module — it is the base of the dependency order, translating mtools' queue and ledger objects into RDF and nothing else, so every other module's behavior can change without adapter.py needing to know [@adapter-is-the-foundation-layer]. Adoption.py — the module that reads whether a repo has adopted mikemol-pathsforward as its own pinned dependency — imports no other nemik module and no RDF library at all; it is pure tomllib and Path, fully independent of the graph-building machinery the rest of the package is built around [@adoption-has-no-internal-coupling]. Nemik-metrics and nemik-serve are the two hub modules — each imports adapter, blocks, wake, and check, the full lower stack — which is the honest shape of "read-only view over everything": neither is modular with respect to the rest of the package, and no third module reaches that same width [@hub-modules-depend-on-everything-below]. The import graph among nemik's own modules has no cycle — adapter, then blocks, adoption, then check, then wake, then metrics, serve is a strict layering, checked by traversal rather than asserted by convention [@import-graph-is-acyclic], but this is the modularity gap: rdflib itself is not encapsulated behind adapter.py — blocks.py, check.py, wake.py, metrics.py, and serve.py all import rdflib directly to build or query graphs of their own, so adapter.py is the sole boundary onto mtools' data model but NOT a boundary onto RDF as a technology; swapping the graph library would touch every module, not one [@rdf-is-not-centralized-behind-adapter]. And even the mtools boundary has one crack: check.py imports mtools' UnreadableStateError directly rather than through a re-export adapter.py provides, so the single-writer claim above holds for parsing the queue but not for naming what happens when parsing fails — a second, smaller seam onto the same upstream package, left open rather than silently claimed closed [@check-py-bypasses-the-adapter-boundary].

## Honest Limits

Nemik has no schema version negotiated between itself and the workstreams it reads — shapes.ttl changes (like the September 2026 title-length refinement, nemik:W23) take effect fleet-wide the moment this repo's shapes.ttl is edited, with no way for an individual workstream to pin an older ruleset or be warned it is about to see new Warnings; conformance drift is discovered by running nemik-check, not declared in advance [@no-versioned-schema]. Nemik itself never writes a queue or a ledger — every script in this package is a reader; the only writer of paths-forward.json and .ledger in the entire fleet is mikemol-pathsforward, invoked directly by each repo's own agent — so nemik's guarantees are guarantees about what it can SEE, not about what it can enforce at write time [@no-write-path].
